# 큐레이션 및 캘리브레이션 (Selection & Calibration)

## 기사가 추천 큐레이션으로 선정되는 과정

1. **수집 및 적재**: 동일 URL, 동일 콘텐츠는 단 1개만 보존합니다. 일반 기사가 제목이나 요약만 포함된 경우 정보원 규칙에 따라 본문을 추가 추출합니다. 동영상 재생 페이지는 제공된 텍스트 설명만 사용하며 플레이어 자체 HTML을 본문으로 간주하지 않습니다. 신뢰할 수 있는 발행 일시가 확인되지 않은 자료는 일단 공개하지 않으며, 원문의 발행 날짜가 파싱된 후 최신성 여부를 판단합니다([정보원 문서](sources.md#규칙-과거-기사-도배-방지)의 "과거 기사 도배 방지" 참조).
2. **사전 필터링 (`prefilter.md`)**: 우리 산업 분야와 관련된 소식인지 1차 검사합니다. 명백히 무관한 것만 걸러내는 완화된 기준을 적용합니다. `BLOCK`으로 판정된 자료는 모든 공개 페이지에 노출되지 않으며, `PASS`와 판단이 모호한 `UNKNOWN`은 다음 단계로 진행합니다. 본문, 피드 요약, 게시글 텍스트가 전혀 없고 제목만 존재하는 일반 기사는 텍스트가 보충될 때까지 대기하며, 채점하지 않고 제목만으로 요약을 작성하지도 않으며 공개 풀에 진입하지도 않습니다(수정본 유입 시 재판정). 본문 없이 노출 가능한 원문 게시물은 기존 채점 및 원문 표시 규칙을 따릅니다.
3. **2회 독립 채점 (`selection-score.md`)**: 동일한 채점 기준을 바탕으로 LLM이 서로 독립적으로 두 번 점수를 매깁니다(0–100점). **두 점수의 합 ≥ 2 × 커트라인**이어야 점수 기준을 통과합니다. 커트라인은 정보원의 신뢰도 등급(Tier)에 따라 다르며, 특정 소스 카테고리는 커트라인을 더 높게 설정할 수 있습니다. 점수가 통과된 기사도 6단계의 중복 검증을 통과해야 최종 큐레이션에 진입합니다. 화면에 표시되는 점수는 두 점수의 평균값(내림)입니다.
4. **구조화 (`structure.md`)**: 채점과 동시에 진행됩니다. 카테고리와 태그(실제 화면에 표시되는 값), 주체를 식별하고, 이 기사가 구체적인 단일 뉴스인지, 여러 이슈를 다룬 종합 브리핑인지, 아니면 정보가 부족해 불분명한지 판단합니다. 단일 구체 뉴스인 경우 팩트 프레임(누가, 무엇을, 대상에게, 언제)과 출처, 전제 조건을 정형 추출합니다. 이 데이터는 테마 페이지, 사건 클러스터링, 일일 상황보고 편성에 핵심으로 사용됩니다.
5. **제목 및 요약 작성**: 구조화 완료 후 작성 단계로 진입합니다. 입선작 및 입선에 근접한 기사(평균 점수가 `understandFloor` 이상인 경우)는 `content-understanding.md`에 따라 한국어 제목, 결론 우선(Answer-first) 요약, 선별 근거를 작성합니다. 그 외의 기사는 `summarize-*.md`에 따라 짧은 제목과 요약을 작성하여 "전체 동향"으로 진입합니다. "전체 동향"(웹 목록, API, Agent 최신 피드, MCP 전체 모드, 전체 RSS)을 조회할 때는 평균 점수가 `browseFloor` 이상인 자료만 노출되며, 점수를 매기지 않은 자료는 정상 노출됩니다(검색 시에는 전체가 검색됨). X(트위터) 게시물에 본문이 없거나 링크만 있는 경우 원문의 링크, 이미지, 인용을 유지하며 작성/번역 모델을 호출하지 않습니다. 작성된 텍스트가 `industry/wording.ts`에 지정된 금지 단어를 사용한 경우 모델이 1회 수정합니다(`mend-wording.md`).
6. **사건 묶기(클러스터링) 및 중복 방지 (`group-*.md`)**: 서로 다른 출처가 보도한 동일 사건을 하나의 '사건(Event)'으로 묶고, 사건 페이지에 종합 개요(`story-digest.md`)를 생성합니다(수정 전 [사건 개요 평가](story-digest-evaluation.md)로 병렬 비교 가능). "실시간 핫이슈"는 이 사건 단위로 순위가 매겨집니다. 점수 기준을 넘은 기사라도 클러스터링이 완료되어야 큐레이션에 정식 진입합니다. 모델은 이 기사가 큐레이션에 이미 선정된 기사와 동일한 뉴스인지, 아직 다루지 않은 새로운 구체적 정보를 담고 있는지 함께 판단합니다.
   - 동일한 뉴스를 다룬 여러 보도는 모두 선정될 수 있으나 웹 화면에서는 하나의 읽기 그룹으로 접힙니다. API, RSS 및 동기화 인터페이스에서는 뉴스당 대표 기사 1건만 노출됩니다. 1차 공식 출처가 최우선이며, 그 다음은 검증된 공식 계정(`publisherRole`과 `owner_entity_id`가 설정된 `T1_5` 계정, 기관이 개인보다 우선), 전문(Full-text) 보유 기사, 점수가 높은 기사, 먼저 발행된 기사 순입니다.
   - 동일 뉴스는 아니지만 새로운 정보가 없는 기사(기존 발표 기능의 재탕 설명, 단순 타 플랫폼 입점 소식 등)는 큐레이션에 진입하지 못하고 "전체 동향"에 남습니다. 종합 기사는 독립 사건을 생성하지 않고 언급된 개별 사건 하위로 귀속되며, 큐레이션에 다루지 않은 중요한 내용이 있을 때만 입선합니다. 정보가 부족한 기사는 입선되지 않습니다.
   - 명시적으로 철회된 보도는 과거 소속 기록은 보존하되 이후 클러스터링 후보 검색, 후보 대표, 사건 시작점, 자동 사건 비교에서 제외되며 동일 URL 및 X 답글/인용에서도 정체성 근거로 사용되지 않습니다. 동일 팩트에 유효 보도가 남아 있으면 유효 보도를 사용하며, 요약만 표시되거나 아직 공개 전인 기사는 철회로 간주하지 않습니다.
   - 클러스터링 확인 전까지 기사는 "전체 동향"에 머물며 자동으로 강제 방출되지 않습니다. 모델 호출이 실패하거나 포맷이 어긋나면 해당 기사는 대기 상태로 유지되며, 대기가 10분을 초과하면 알림이 발생하고 관리자 대시보드 "운영" 페이지에 표시됩니다. 관리자는 "콘텐츠 진단"에서 해당 기사를 열고 "재클러스터링"을 수동 실행할 수 있습니다.
7. **일일 상황보고 · 주간 정세평가 · 월간 전략평가 발간**:
   - **일일 상황보고**: 매일 08:00에 발행되며(발행 시각은 `site/site.ts`의 `EDITION_TIMES`에서 변경 가능), 전날 08:00부터 당일 08:00까지의 데이터를 알고리즘 규칙에 따라 편성합니다. **LLM을 호출하지 않고 결정론적 규칙으로 편성**합니다. 사건당 1건의 기사(가장 권위 있는 출처)를 선정하고, 동일 사건의 당일 후속 진척은 하단에 배치하며, 종합 기사는 언급한 가장 중요한 사건 아래에 연결합니다. 최근 7일 내 보고에 이미 실린 사건은 다시 등장하지 않으며, 후속 진척이 있을 때만 다루되 당사자의 직접적인 새 조치(`commentary` 분류 제외)가 있거나 4개 이상의 소스가 보도했을 때만 본문에 오르고 나머지는 1줄 단신으로 분류됩니다. 선정 보도는 없지만 공식 원문 게시물과 3개 이상의 독립 참여자가 있는 사건도 보충 포함됩니다(일보에만 수록되며 푸시하지 않음). 중요도 순으로 상위 12건이 본문에 들어가고 동일 정보원은 최대 2건까지만 허용되며, 그 외에는 최대 10건의 1줄 단신이 추가됩니다. 첫 번째 기사가 톱기사(헤드라인)가 되고 2~4번째 기사가 주요 하이라이트로 배치됩니다.
   - **주간 정세평가(월요일 10:00)** 및 **월간 전략평가(매월 1일 10:30)**: 해당 주, 해당 월의 일일 보고 데이터를 종합하여 편성합니다. 며칠에 걸쳐 다뤄진 사건은 1건으로 합산되며, 주간 보고는 상위 20건, 월간 보고는 상위 30건을 추출합니다. 모델(`report-period.md`, `report-period-sections.md`)은 전체 총괄 브리핑과 3건 이상의 섹션에 대한 1줄 리드문만 작성하며, 기사 목록을 임의로 추가하거나 삭제할 수 없습니다. 모델이 기사 본문에 없는 새로운 주체명이나 수치를 임의로 지어낼 경우 해당 설명문은 폐기되고 템플릿 기반 기본 문구로 자동 대체됩니다(`PLAIN_TERMS` 및 사이트명 제외).
   - 각 큐레이션 기사는 단 1회의 리포트에만 포함됩니다. 마감 시간 이후 확정된 기사는 다음 호에 수록됩니다.
   - 매 30분마다 확인하여 정시가 된 호를 1회 발간하며 누락되거나 실패한 호는 보충 발간됩니다. 기간 내 판단된 자료가 있으나 새 사건이 없으면 빈 호를 발행하고, 판단된 자료 자체가 전혀 없으면 실패로 간주하여 결호 알림을 보냅니다. 주간/월간 기간 내 모든 일일 보고가 존재하나 원본 항목이 전부 비어 있으면 빈 리포트를 생성하지 않고 자동으로 건너뜁니다.

각 단계의 프롬프트는 모두 `industry/prompts/`에 위치하며, 프롬프트의 버전은 내용의 해시값으로 관리됩니다. 프롬프트를 수정하면 이후 새로 유입되는 자료부터 새 버전이 적용되며 과거 데이터는 소급 재계산되지 않습니다.

## 선정 커트라인: `industry/selection.ts`

```ts
export const SELECTION = {
  thresholds: { T1: 60, T1_5: 65, T2: 76 },   // 두 채점 점수의 평균이 최소 이 점수 이상이어야 함
  classes: {                                  // 특정 소스 카테고리: 이 카테고리는 커트라인이 상향 조정됨
    ecosystem: { label: "방산·사이버 인프라", threshold: 70 },
    leaderboard: { label: "싱크탱크·평가 리포트", threshold: 76 },
  },
  understandFloor: 50,                        // 입선에 실패했으나 이 점수보다 높은 기사는 입선작과 동일한 고품질 요약 작성
  browseFloor: 40,                            // "전체 동향" 열람 시 이 점수 미만의 기사는 피드에서 숨김 (검색 시에는 노출)
};
```

1차 공식 소스(T1)는 커트라인이 상대적으로 낮고, 미디어와 개인(T2)은 상대적으로 높습니다. 동일한 사실이라도 공식 발표 원문이 우선적으로 노출되어야 하기 때문입니다. 커트라인이 없는 등급(`EXCLUDE_MP`)은 선별에 참여하지 않습니다.

특정 공식 소스는 일상 업데이트가 많아 일반 독자에게는 핵심 사건만 보여주고 싶을 수 있습니다. 이 경우 관리자 "정보원" 페이지에서 해당 소스에 `classes` 카테고리를 지정하면 커트라인을 하한선 이상으로 높일 수 있습니다(상향만 가능, 하향 불가; 배포 후 키 이름 변경 금지).

`browseFloor`를 `0`으로 설정하면 점수에 관계없이 모든 수집 기사가 "전체 동향"에 표시됩니다.

## 캘리브레이션 (Calibration)

### 1. 골드 데이터셋(Gold Dataset) 준비

보유한 정보원에서 100~200개의 기사를 선별하여 "선정해야 함 / 선정하지 말아야 함"을 사람이 직접 라벨링하고 `.data/gold.jsonl` 파일로 저장합니다(`.data/` 디렉터리는 Git 추적에서 제외됨). 한 줄에 JSON 1개씩 작성합니다:

```json
{"caseId":"law-001","material":{"title":"원문 제목","originalTitle":null,"publishedAt":"2026-10-01T09:00:00+08:00","sourceName":"정보원 이름","bodyZh":null,"bodyOriginal":"본문 내용..."},"sourceFacts":{"sourceKind":"rss","sourceTier":"T1","firstParty":true,"language":"ko"},"samplingContext":{"benchmarkSplit":"development","samplingStratum":"regulation"},"gold":{"decision":"select"}}
```

| 필드 | 설명 |
|---|---|
| `caseId` | 고유 식별자 |
| `material` | 제목, 원제, 발행 일시, 소스 이름, 본문 |
| `sourceFacts` | 정보원 종류, 신뢰도 등급(Tier), 1차 공식 여부, 언어. 등급에 따라 적용 커트라인 결정 |
| `samplingContext` | 선택 사항. `benchmarkSplit`은 개발 세트(`development`)와 검증 홀드아웃 세트(`holdout`)를 구분하며, `samplingStratum`은 자체 분석용 카테고리 |
| `gold.decision` | `select`(선정 대상), `reject`(탈락 대상), `either`(판단 보류/중립 - 정확도 분모에서 제외) |

`industry/gold.example.jsonl`에 샘플 데이터가 들어 있습니다.

**데이터셋 구축 팁**:
- **어려운 케이스(Hard Cases)**를 많이 포함하세요. 아슬아슬하게 통과해야 할 기사나 아슬아슬하게 탈락해야 할 기사를 많이 넣어야 튜닝 효과가 큽니다.
- 프롬프트 튜닝 시에는 개발 세트만 보고 조정하고, 마지막에 홀드아웃 세트로 일반화 성능을 검증하세요.
- 평가 스크립트는 사전 선별과 2회 채점만 실행하며 중복 검증은 포함하지 않으므로, 기사 자체의 가치만을 기준으로 라벨링하세요.

### 2. 평가 실행

```bash
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split development --label "1차 개정 평가 기준"
```

평가 도구는 각 샘플에 대해 사전 선별과 2회 채점을 수행한 뒤 다음을 출력합니다:

- **유효 출력 정확도, 정밀도(Precision), 재현율(Recall), F1 스코어**: 유효한 판단을 완료한 비-`either` 샘플 대상 지표.
- **커버리지(Coverage)**: 전체 비-`either` 골드 샘플 중 모델이 에러 없이 정상적으로 판단 결정을 내린 비율.
- **완전 정확도(Complete Accuracy)**: 모델 호출 실패나 포맷 오류까지 오답으로 간주하여 전체 비-`either` 골드 샘플을 분모로 계산한 정확도(`either`는 항상 분모에서 제외되며 실패 건수만 별도 기록).
- 커트라인 점수를 40점에서 90점까지 2점 단위로 시뮬레이션한 점수대별 스캔 결과 (`site/site.ts`의 `DEPLOYMENT.selectionGold`로 기본 파일, 샘플 수, 분할, 스캔 범위 지정 가능).
- 오판한 기사 목록 및 상세 리포트가 `.data/eval/`에 기록되며 관리자 대시보드의 **SelectBench**로 자동 임포트됩니다(`--no-import`로 생략 가능).

`--models`를 지정하지 않으면 현재 "선별 채점" 단계에 설정된 모델을 사용하며, `--models default,deepseek-flash`처럼 여러 모델을 비교할 수 있습니다. 동일 실행 내에서 렌더링된 채점 입력이 같은 샘플들은 모델 응답과 실패를 공유하며, 재실행 시 기존 영수증을 재사용합니다(보고서의 토큰/소요시간은 해당 영수증 누적 기준).

### 3. 오판 사례 분석 및 프롬프트 개선

관리자 SelectBench에서 모델이 오판한 사례와 모델이 제시한 근거를 분석합니다(다중 모델 보고서 업로드 시 동일 `caseId`의 `gold` 라벨이 충돌하면 거부됩니다):

- **선정되어야 하는데 탈락한 경우**: 채점 프롬프트(`selection-score.md`)에서 해당 소식이 왜 중요한지에 대한 가치 기준이 누락된 것입니다. "반드시 정상 평가해야 할 가치" 섹션에 해당 유형과 예시를 추가합니다.
- **탈락해야 하는데 선정된 경우**: 노이즈 억제 규칙이 약한 것입니다. "반드시 억제해야 할 노이즈" 섹션에 해당 케이스를 명시합니다.
- **전반적으로 점수대가 너무 높거나 낮고, 오판 사례들이 커트라인 언저리에 몰려 있는 경우**: 그때 비로소 `industry/selection.ts`의 커트라인 점수를 미세 조정합니다.

> [!TIP]
> 반드시 프롬프트를 먼저 개선하고, 커트라인 숫자는 마지막에 조정하세요. 커트라인 숫자는 전체를 일괄적으로 올리거나 내릴 뿐 특정 카테고리의 오판을 해결해주지 못합니다. 모델 비교 시에도 유효 F1만 보지 말고 커버리지와 완전 정확도를 함께 확인하세요.

## 모델 교체

관리자 대시보드의 "모델 및 평가" 페이지에서 파이프라인의 각 단계별로 현재 사용 중인 모델, 최근 성공률, 응답 시간, 토큰 사용량을 모니터링할 수 있으며 즉시 다른 모델로 교체할 수 있습니다. 채점 모델을 교체하기 전에는 `--models` 옵션을 사용해 동일한 골드 데이터셋에서 기존 모델과 후보 모델의 F1 스코어를 먼저 비교해 보세요.
